## TODO-01 · 延迟图对极高值的处理

- **现状**：延迟图按真实采样绘制，「平滑峰值」只调整曲线的绘制平滑度（0.1 ↔ 0.6），不改写、不过滤、不插值。个别尖峰（实测 1200ms 对正常 200ms）会把其余区间压扁，可读性下降。
- **上游做法**：`cutPeakValues` 先把与邻域均值（窗口 15）偏离超过 30% 的点置空，再用 EWMA（α=0.3）重写整条序列并用运行值填补空洞；且无论开关状态，上游都会先跑 `interpolateNullsLinear`（相邻有效点间隔 ≤ 中位数 × 6 时线性插值，钳制 2–30 分钟）。也就是说上游画出的线已不是采样值本身。
- **待决策**：
  - **A** 保持现状（真实，但尖峰压缩可读性）；
  - **B** 1:1 移植上游的削峰与插值 —— 与「不改写采样、不插值」的数据真实性边界直接冲突，需要明确授权，并应在图上标注数据已平滑；
  - **C** 不动数据，只改坐标轴可读性（按 P99 缩放或对数轴开关），尖峰仍在且悬浮可读真实值。
- **影响文件**：`src/domain/detail-chart-options.ts`、`src/components/detail/PingChart.vue`。

## TODO-02 · CFSM 不支持的两项设置的最终处理

- **现状**：`rpcTransportMode` 与 `visitorInfoEnabled` 已从设置页移除；两项仍保留在 `theme/settings.ts` 的 48 项 schema 与 `POST /api/theme_options` 的完整快照中，因为保存协议要求发送完整对象。
- **复核依据**：CFSM 公开接口只有 REST 与 `/api/ws`，后端源码与 `theme-develop.md` 中都不存在 RPC 传输层；在 CFSM 整个 `src/` 中搜索 `CF-Connecting-IP` / `visitor` / `访客` 零命中，没有任何接口把访客 IP 或审计数据交给主题。
- **待决策**：正式版是否把这两项一并从 schema 中移除。移除会改变保存快照的键集合，需要先确认与旧版本互相覆盖时的兼容行为（现有「未知后端键原样回传」的规则是否足够）。
