# CFSM Glassmorphism v1.1.0-test.5（测试版）

> 本版本用于 CFSM / 探针数据契约审计与真实功能 Bug 修复的专项验证。允许存在已记录且不阻塞的上游限制与待裁决 UI 冲突，不代表所有数据/逻辑问题均已修复。

> **这是测试版，不是稳定版。** 生产环境请继续使用
> [v1.0.0](https://github.com/allury/CFSM-Glassmorphism/releases/tag/v1.0.0)。

本版本基于 `v1.1.0-test.4`。与前几轮不同，本轮**先读源码再改代码**：
完整审读 CF-Server-Monitor Worker `2.8.5 Beta5` 与探针 Agent `1.3.8` 的采集、上报、存储、
REST、WebSocket 与 History 全链路，建立字段级数据契约，再按契约审计当前实现并修复真实 Bug。
所有结论都能回指到具体源码位置或真实部署的响应样本。

第 11 轮首页与第 13 轮详情页的 1:1 成果全部保持不变，本轮已逐项回归。

## 修复的真实 Bug

### BUG-001 · 首页延迟 / 丢包柱状图时间轴错位

`/api/servers` 的 `servers[].ping` / `loss` 是**时间桶序列**：服务端固定输出 20 个点、
覆盖 2 小时，每个点包含全部 8 个探测目标，取值为 数值 / `null`（该桶无采样）/ `false`（未配置）。

本主题此前把「20 个时间桶 × 4 条线路」拍平成一维数组，还顺手过滤掉了空洞。
浏览器实测渲染出 **68 根**柱子而不是 20 根：柱子既不是时间序列、数量随缺口变化、
也和面板标注的线路对不上，一个空洞就会让后续柱子整体前移。

现在按上游 `useNodePingDisplay` 的做法一桶一柱，只画面板所标注的那个探测目标，
`null` 保留为原位的空洞柱。柱高与五级 signal 色阶不变。

### BUG-002 · 首页整段丢掉 `node_1`～`node_4` 探测目标

`GlassServer.latency` 被限定在旧四线路，而 CFSM `mergeMetricsIntoServer` 写入全部 8 个目标，
`/api/config` 也提供 `node_1_name`～`node_4_name`。结果：CFSM 2.8.5 起新增的 4 个探测点
在首页从不显示（详情页反而是对的）。只配置了 node 探测点的节点，首页探针区完全空白。

现在首页与详情页统一走 8 个目标。

### BUG-003 · 站点级 `show_price` / `show_expire` / `show_tf` 完全失效

这三个开关只出现在 `/api/servers` 响应的**顶层** `sysConfig`：`/api/config` 没有，
`/api/server` 的 `sysConfig` 只有 `long_history_points`（真实部署实测 `{"long_history_points":180}`）。

本主题解析了集合级 `systemConfig` 却**没有任何消费者**，而 `toGlassServer` 读的是
每台节点上的 `systemConfig`（列表里恒为 `undefined`）。实测把三个开关全部关掉后，
价格芯片、剩余天数与流量配额照常显示——运营方的隐藏设置形同虚设。

现在集合级开关会下发到每台节点，详情页通过 `useServersStore.siteVisibility(base)`
按 owning source 取回同一组开关；剩余价值卡也跟随价格开关一起隐藏。

### BUG-004 · 总览卡片单位抢占主数值宽度

`.overview-card__unit` 此前写了 `flex: none` + `max-width: 60%`，等于把单位钉死并硬占六成宽度，
主数值只能拿剩下的四成。768px 实测 `455.0` 被截成 `45…`，而同宽度下上游能显示更多位数。
上游那个单位只有 `truncate`，既不固定也没有宽度上限。

修正后 390 / 768 实测空间分配与上游一致。注意详情页指标卡的单位上游写的是 `shrink-0`，
因此那边保持固定，两者不互相套用。

## 复核结论有变化的既有 KNOWN-BUG

- **BUG-001（旧）**：旧结论「样本条数少于上游，视觉结构已对齐」只对了一半。
  20 点 / 2 小时确实是服务端写死的常量（改记为上游限制），
  但「视觉结构已对齐」是错的——真正的错位 Bug 就藏在里面，本轮已修。
- **BUG-002（旧）**：面板数值本就区分 `false` / `null` / 真实 0，本轮修完柱状图后
  空洞也有独立表现，该条**关闭**。

## 不是 Bug 但容易被误读的一处

详情页探针卡显示 `Loss 0.0%`，同页 24 小时丢包历史里却有丢包。用真实节点核对：
标量 `loss_ct = 0`，同节点 24 小时历史 180 行中 170 行为 0、10 行 >0、最大 16%、无 null。

卡片标量取的是**最新一条上报**（服务端 `ORDER BY id DESC LIMIT 1`），
历史是**整段窗口的逐桶采样**，两者同时成立，数据层没有问题。
但 Komari 在同一位置显示的是窗口**平均值**，所以上游不会出现这种视觉反差——
是否改口径属于展示语义变更，已登记为待裁决项，本轮不擅自改动已验收的数值。

## 待裁决与上游限制

- **待裁决**：延迟/丢包面板主数值的口径（当前值 vs 上游的窗口平均）；
  总览卡片长数值在 768px 档仍会截断（与上游同等行为，要完整显示必须动已验收的几何）。
- **上游限制**：首页窗口固定 20 点 / 2 小时；旧库未迁移时窗口只有 4 个 key；
  探针首轮未完成时上报空串会被服务端转成真实的 `0`；详情页深链接冷启动拿不到站点级开关。

逐条见 [`docs/bug-matrix.md`](https://github.com/allury/CFSM-Glassmorphism/blob/main/docs/bug-matrix.md)。
