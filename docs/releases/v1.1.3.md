# CFSM Glassmorphism v1.1.3

<!-- store-label: 详情页请求减半与控件配色 -->

详情页冷启动的接口请求从 6 个减到 4 个，控制类控件按各自应有的取值上色。功能没有删减。

## 变更

- **详情页历史只取一次**：负载图与延迟区此前各自持有时间窗口（24 小时与 1 小时），各发一次 `/api/history/all`。CFSM 的一次响应里负载与 ping 两类序列都在，因此**同一个窗口**不需要请求两次。两张图现在默认共用一个窗口，默认值改为最近 1 小时；切换时间范围时一起切换，仍只发一个请求。延迟图保留自己的时间选择器：选到与负载图相同的窗口复用同一份响应，选到不同窗口才会另取一份。
- **详情页不再重复请求站点配置**：应用启动时取过一次 `/api/config`，详情页又按「节点归属的后端」取了一次。单后端站点上两次是同一个地址、同一份内容，现在直接复用；多 `apiBase` 部署仍按来源单独取。
- **延迟图的时间档位与负载图统一**：此前是子集，共用窗口后会出现窗口落在档位之外、选择器没有选中项的情况。
- **控制类控件的配色按类型分开**：激活态的快捷筛选胶囊跟随毛玻璃配色方案（表面色、文字色与模糊度），分组标签与视图切换用不透明的页面底色加选中色，三者的悬浮态都不再画背景和阴影。此前它们共用同一个表面变量。
- **延迟图在长窗口下给出取样提示**：说明该窗口的数据由服务端分桶取样返回，短时波动可能看不到。

## 修复

- **快速切换时间范围时，先发的慢响应会覆盖后发的快响应**。负载图缺少「窗口是否已被更晚一次切换改掉」的判断，连续点选不同范围时，图上可能留着旧窗口的数据而选择器显示新窗口。延迟图原本就有这道判断，现已补齐到两边。
- 分组标签与视图切换的激活底色此前偏白，与页面底色不一致。

## 勘误（v1.1.4 期间复核）

下一节「关于取样精度」里的这句话**不准确**：「窗口不超过 1 小时：不套用点数上限，返回该区间内的全部上报记录」。此处更正，下一节原文保留不动，便于对照。

复核服务端 `getMetricsHistory`（实读克隆版本 `90d0d21`）：点数上限对两类窗口都存在，只是取值不同——

```js
const maxPoints = queryHours > 1 ? configuredLongHistoryPoints : DEFAULT_HISTORY_MAX_POINTS; // 160
const intervalMs = Math.max(10_000, Math.ceil(samplingDurationMs / maxPoints));
… ROW_NUMBER() OVER (PARTITION BY bucket …) … WHERE rn = 1
```

也就是说 **1 小时窗口同样分桶取样**，桶宽为 `max(10 秒, 窗口 / 160)`，1 小时约 23 秒；只是当上报间隔远大于桶宽时，每个桶里至多只有一条记录，结果才看起来等于「全部返回」。那是数据密度低于桶宽的结果，不是接口的保证。

因此「切到 1 小时可看到该区间内的全部上报记录」这句也应理解为：恢复的是该窗口在更细桶宽下的采样，不构成「不丢任何一条上报」的承诺。

本次不修改任何旧标签、旧发布包或服务端配置（站点 `long_history_points` 保持 180）。

## 关于取样精度

服务端（`getMetricsHistory`）对两类窗口的处理不同：

- **窗口不超过 1 小时**：不套用点数上限，返回该区间内的全部上报记录。点与点的间隔等于节点自己的上报节奏，由站点与节点配置决定，不是接口的固定值。
- **窗口超过 1 小时**：按站点配置的 `long_history_points` 分桶，每个时间桶只取一条记录返回，桶内其余上报不出现在响应里。部分部署会对丢包列取桶内最大值，是否走这条路径取决于该部署的历史表索引优化状态。

因此把窗口调回 1 小时，恢复的是**该区间内的全部上报记录**；它不能保证还原更长窗口里被分桶略过的那些采样。

本主题不做任何再加工：不削峰、不插值、不把缺失值改成 0，`connectNulls` 保持关闭，探测返回 `false` / `null` 与缺列一律按缺失渲染。

## 已知限制

以下各项在本版本中**仍然存在**，不宣称已解决：

- **详情页仍会取一次节点列表**：站点级的价格 / 到期 / 流量显示开关只出现在 `/api/servers` 的 `sysConfig`，`/api/server?id=` 的同名字段里没有；上一台 / 下一台与节点选择器也需要这份列表。该请求带守卫，只在直接打开或刷新详情页时发生一次，从首页点进详情页不会触发。
- **延迟图的极高值**：「曲线平滑」只改变折线曲率，不重写、不过滤、不插值任何采样值，因此个别尖峰仍会压缩常态区间的可读性。
- **对话框输入框与描边按钮未接入配色方案**：这两类元素使用自己的表面色，不随配色方案变化。它们不在首页控制条上，本版本未改动。
- **移动端触屏未实测**：统计卡在窄屏下会截断，完整值由提示气泡承担。气泡在真实触屏设备上的唤出方式没有实机证据，模拟器派发的仍是鼠标事件。
- **真实环境未覆盖的边界场景**：验收站点的节点未出现超长节点名、超长系统名、无价格 / 免费、已过期、无探测目标、离线节点与稀疏字段等情形，这些场景只有本地构造样本的覆盖。
- **多 `apiBase` 缺少实机证据**：验收站点为单后端，多来源部署下必须保留 `?source=` 与按来源取配置的分支只有单元测试与本地覆盖，没有真实环境验证。

## 验证

- 代码检查、类型检查、单元测试（371 项）、构建与产物校验均已通过。新增的请求预算用例驱动真实 store 与打桩网络，逐条断言单后端、多 `apiBase`、共用窗口、联动切换与独立窗口下的请求数；覆盖用例把响应按 URL 延迟返回，制造「先发的后到」，断言最终留在图上的是后发窗口的数据——补判断之前这条用例会失败。
- 控件配色取值来自同机、同浏览器、同视口下的真实交互实测（点击而非读类名），并在四套内置配色方案与明暗两种主题下逐一复验；`--glass-strong` 全程未变，提示框、菜单与弹层不受配色方案影响。
- 浏览器实测冷启动打开详情页：`/api/config`、`/api/server`、`/api/history/all`、`/api/servers` 各一次，合计 4 个请求，此前为 6 个。

## 安装

在 CFSM 后台「主题商店 → 自定义主题 URL」中填入不可变标签：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.3
```

也可以下载本页的 `CFSM-Glassmorphism-v1.1.3.zip` 手动安装：解包后，将根目录的 `index.html` 与 `assets/` 部署到主题目录。

回退入口：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.2
```
