# CFSM Glassmorphism v1.1.0（正式版）

第二个正式版，取代 [v1.0.0](https://github.com/allury/CFSM-Glassmorphism/releases/tag/v1.0.0)。

本版本汇总了 `v1.1.0-test.1` ～ `v1.1.0-test.5` 五个测试版的成果，并在此基础上完成了
字体一致性专项验收、详情页历史图表配色修复，以及若干遗留项的重新裁决。

## 这一版修了什么

### 详情页历史图表：折线不再是黑的

`/api/history` 的多条折线此前全部渲染成黑色，而同一份数据在 tooltip 色点和
底部摘要色点里颜色又是对的——同一张图前后不一致。

根因不是配色表写错，是**颜色根本没进到画布**：图表走 ECharts 的 `CanvasRenderer`，
序列颜色最终落到 canvas 2D 的 `strokeStyle`，而 canvas **不解析 CSS 变量**。
本主题此前把 `var(--emerald)` 这类值同时用于图表配置和 HTML，
HTML 能解析、canvas 不能，于是折线留在上一次的绘制样式上，也就是纯黑。

现在按上游 `utils/chartPalette.ts` 逐字移植了一份具体色值的调色板，
坐标轴 / 图例 / tooltip 的底色文字色也换成上游 `chartThemeColors` 的同一组 rgba。
画布像素实测：9 张图的绘图区取样从「只有 `0,0,0`」变成
`#FF6B6B` / `#4ECDC4` / `#A78BFA` / `#60A5FA` / `#FFB347`，与底部色点逐一相等；
同一批取样在上游得到同一组色值。

顺带修好的还有：

- **浅色模式下图内图例文字偏白**——同一个根因。现在浅色是 `rgba(0,0,0,0.55)`、
  深色是 `rgba(255,255,255,0.55)`，与上游一致。
- **色觉友好模式**现在会整体切到上游的无障碍调色板（`#0072B2` / `#E69F00` / `#CC79A7`…），
  而不是只改线型；线型也改用上游的 `solid` / `dashed` / `dotted`。
- **主题切换不再残留旧颜色**：坐标轴与图例颜色随浅色 / 深色实时重算。

> 用户反馈的「悬浮网络图时曲线疑似消失」**在本轮候选构建中没有复现**：
> 1440 与 375 两档、绘图区三个横向位置悬浮再移出，两条序列的像素数完全不变。
> 相关事实与后续排查方式记在 `docs/chart-parity.md`，请在实际使用中继续留意。

### 字体一致性

以 Komari `bf83765` 为基准逐项对照后修掉的差异：

- 字体栈逐字照抄上游，去掉本主题自行追加的 `"Microsoft YaHei"`，
  并删除 Vite 模板带来的 `font-synthesis: none` 与 `text-rendering: optimizeLegibility`
  （上游两条都没有）。
- 首页节点卡的指标数值、延迟 / 丢包面板数值：字重 600 → **500**。
  这不是纸面差异——该字族只有 Regular 与 Bold 两档实体字面，
  500 落 Regular、600 落 Bold，整列数字此前都比上游粗一档。
- 详情页徽章：11px / 600 → **12px / 500 / line-height 16px**，高度也因此从 20.5px
  变成与上游 `h-5` 相等的 20px。
- 站点名与详情分区标题：改回上游的 600，并去掉本主题自造的负字距。
- 历史图表 tooltip 字号 11 → **12**，与上游一致。

六档视口（375 / 390 / 768 / 1024 / 1440 / 1920）× 浅色深色逐项复核，
第 11 轮首页与第 13 轮详情页的几何全部保持原值：
首页节点卡仍是 `[91,337,303,333.75]`、总览卡 `201.33×96`、控制条 `[91,289,1248,32]`；
详情页顶栏 `[91,57,1248,32]`、指标卡 `300×96`、信息栅格 `[91,329,1248,353]`、
信息卡高 `223/223/114/114`。

### 详情页直达链接时的站点开关

`show_price` / `show_expire` / `show_tf` 只出现在 `/api/servers` 的顶层 `sysConfig`。
从首页点进详情没问题，但**直接粘贴详情链接**时拿不到，运营方特意隐藏的
价格、到期与流量配额照常显示。第 14 轮把它记成了上游限制，本轮推翻了这个结论：
补一次**首页本来就在用的**同一个列表请求即可，不需要新的请求形态。

现在详情页在本地还没有节点列表时会补发一次 `/api/servers`（只发一次，不轮询），
并且在开关拿到之前**先隐藏**相关卡片——宁可晚一点显示，也不把运营方关掉的价格闪出来。
顺带把冷启动时空着的「上一台 / 节点选择器 / 下一台」也补齐了。

实测 `showPrice=0&showExpire=0&showTf=0` 直达详情：修复前 8 张指标卡全在，
修复后只剩「累计流量 / 运行时间 / 连接数」，`/api/servers` 恰好 1 次。

### 被截断的总览数值现在读得出来

768px 的六列栅格下，总览卡内容宽度只有 90 多 px，`455.0` + `GB / 1.56 TB` 放不下。
截断本身与上游同等（本主题分给主数值的宽度反而更多：43px 对 38px），
但上游那三张卡**根本没有 tooltip**，完整值在两边都无从读取。

本轮没有动任何几何，只把本主题**已有**的 tooltip 内容补全：
内存 / 硬盘 / 交换内存现在会给出完整的「已用 / 总量」加占比；
系统分布与地区分布改用上游 `formatDistributionTooltip` 的完整列表，
长系统名（如 `Ubuntu 24.04.4 LTS`）被截断后仍然可读。

## 已知差异与未解决项

这一版**不声称**与上游像素级一致，以下三项已记录在 `docs/bug-matrix.md`：

- **行高**：本主题多处用 `line-height: normal`，上游是 Tailwind 的具体值，
  每行小 1～2.5px。但这个偏差被本主题更大的内边距抵消了——
  把上游行高逐项注入后，节点卡高度反而从 `333.77` 变成 `335.34`，
  离上游的 `331.81` 更远。单独对齐行高会让几何更差，需要连同盒模型一起重做，
  留待专门一轮处理。
- **图表形态**：上游 `LoadChart` 内联的 CPU / 内存 / 磁盘 / 网络 / GPU 图带渐变填充、
  线宽 1.5；本主题统一走上游 `MetricSeriesChartCard` 的纯折线形态、线宽 1.6。
  逐图对照表见 `docs/chart-parity.md`。
- **延迟 / 丢包面板主数值的口径**：本主题显示的是**最新一条上报**
  （服务端 `ORDER BY id DESC LIMIT 1`），上游显示的是窗口**平均值**。
  本轮已复核来源、更新时间与目标对应关系均正确，`null` / `false` / 缺失都没有变成 0，
  因此不是数据错误；但「卡片显示 0% 而历史图里有丢包」这种视觉反差依然存在，
  作为未解决的展示歧义继续登记。

上游限制（窗口固定 20 点 / 2 小时、旧库未迁移时窗口只有 4 个 key、
探针首轮空串会被服务端转成真实 0、详情端点不返回温度）保持第 14 轮结论。
其中「旧库 4 个 key」在升级到 `2.8.5 Beta5` 并完成迁移后不再触发。

## 验证

- 25 个测试文件、244 个测试全部通过；本轮新增
  `tests/typography-contract.test.ts` 与 `tests/chart-colors.test.ts`。
  图表测试断言的是「进入图表的颜色一定是 canvas 能解析的具体值」，
  而不是「源码里出现过某个颜色字符串」。
- lint、typecheck、build、产物校验与 `git diff --check` 全绿。
  typecheck 按 `AGENTS.md` 的规定用仓库外的便携 Node 复跑，确认 vue-tsc 真的分析了 SFC 模板。
- 真实浏览器验收：两套 localhost 同时运行，逐项 `getComputedStyle` /
  `getBoundingClientRect` / `getImageData` 对照；覆盖六档视口、浅色深色、
  默认与色觉友好、首次加载 / 直达 / 刷新 / 返回后重进、悬浮与移出、时间范围切换。
  控制台无错误。
- 用真实部署（`sr.706632.xyz`，本轮实测 Worker `2.8.5 Beta5`）交叉验证了
  窗口形态、顶层 `sysConfig` 与探针三态。
